# E2E Encryption (Zero-Knowledge Cloud Storage) Entegrasyon Planı

## 1. Genel Bakış

**Amaç:** Kullanıcı fotoğrafları, ses kayıtları ve diğer medya dosyaları E2E şifreleme ile buluta yüklenecek. Uygulama sahibi (sen) dahil hiç kimse şifrelenmiş verilere erişemeyecek.

**Temel Mantık:**
- Kullanıcı password ile giriş yaptığında, cihazda saklanan KEY ile dosyalar şifrelenir/yeniden çözülür
- Firebase Storage'da sadece şifreli baytlar durur
- Şifre çözme işlemi sadece kullanıcının cihazında yapılır

---

## 2. Mevcut Sistem Analizi

### 2.1 Şu Anki Durum
- Medya dosyaları (fotoğraf, ses) sadece **yerel depolama**'da (`documents/images/`, `documents/audio/`)
- Cloud yedekleme sadece **metadata** içerir (veritabanı kayıtları)
- Dosyaların kendisi Firebase Storage'a **yüklenmiyor** (`[DISABLE_STORAGE]` yorum satırı)
- Sonuç: 3 gün sonra / cihaz değişince fotoğraflar kayboluyor

### 2.2 Hedef Durum
- Tüm medya dosyaları AES-256 ile şifrelenip Firebase Storage'a yüklenecek
- Kullanıcı aynı hesapla giriş yaparak tüm cihazlarından dosyalarına erişebilecek
- Uygulama sahibi dahil **kimse** şifreli verileri göremeyecek

### 3.3 Şifreleme Detayları

| Parametre | Değer | Açıklama |
|----------|-------|----------|
| Algoritma | AES-256-CBC | Endüstri standardı |
| Key Derivation | PBKDF2 | 100,000 iterations, SHA-256 |
| Salt | 16 bytes rastgele | Her kullanıcı için benzersiz |
| IV | 16 bytes rastgele | Her dosya için benzersiz |
| Storage Format | IV (16) + Encrypted Data | Byte dizisi |

## 6. Riskler ve Çözümler

| Risk | Olasılık | Etki | Çözüm |
|------|----------|------|-------|
| Şifre unutulursa veri kaybı | Orta | Yüksek | Recovery key sistemi (opsiyonel faz 2) |
| İlk yükleme çok yavaş | Düşük | Orta | Background job + compression |
| Cihazda KEY çalınırsa | Çok düşük | Yüksek | Keychain zaten şifreli, ek PIN koruması |
| Firebase storage quota aşımı | Orta | Düşük | Lazy loading, silinen dosyaları temizle |
| Migration sırasında hata | Düşük | Yüksek | Transaction + rollback mekanizması |
| Password change sırasında veri kaybı | Çok düşük | Yüksek | Önce yeni KEY oluştur, sonra eski dosyaları çöz-yeniden şifrele |

## 12. Fotoğraf Sıkıştırma

### 12.1 Compression Pipeline

```
Fotoğraf Çekildi
      ↓
1. JPEG encode (quality: 80%)
      ↓
2. Boyut kontrol (>5MB ise tekrar sıkıştır)
      ↓
3. E2E şifrele (AES-256-CBC)
      ↓
4. Firebase Storage'a yükle
      ↓
5. Cloud path'i Firestore'a kaydet
```

### 12.2 Kod Örneği

```dart
import 'dart:io';
import 'dart:typed_data';
import 'package:flutter_image_compress/flutter_image_compress.dart';

class ImageCompressor {
  /// Fotoğrafı sıkıştır ve Uint8List döndür
  Future<Uint8List> compressAndGetBytes(String imagePath) async {
    final result = await FlutterImageCompress.compressWithFile(
      imagePath,
      quality: 80,
      minWidth: 1920,
      minHeight: 1080,
      format: CompressFormat.jpeg,
    );
    return result!;
  }
}
```


### 13.2 Kod Örneği

```dart
import 'package:local_auth/local_auth.dart';

class BiometricService {
  final LocalAuthentication _auth = LocalAuthentication();

  Future<bool> isAvailable() async {
    return await _auth.canCheckBiometrics;
  }

  Future<bool> authenticate() async {
    try {
      return await _auth.authenticate(
        localizedReason: 'Dosyalarınıza erişmek için doğrulama yapın',
      );
    } catch (e) {
      return false;
    }
  }

  Future<List<BiometricType>> getAvailableBiometrics() async {
    return await _auth.getAvailableBiometrics();
  }
}
```

### 14.2 Migration Adımları

```dart
class E2EMigrationService {
  
  Future<void> migrateLegacyFiles(String userId) async {
    // 1. Eski dosyaları bul (local'de var ama cloud'da yok)
    final legacyFiles = await _findLegacyFiles();
    
    if (legacyFiles.isEmpty) return;
    
    // 2. Progress başlat
    _reportProgress('Güvenlik güncellemesi başlıyor...', 0);
    
    // 3. Her dosyayı şifrele ve yükle
    for (int i = 0; i < legacyFiles.length; i++) {
      final file = legacyFiles[i];
      
      // Sıkıştır
      final compressed = await ImageCompressor().compressAndGetBytes(file.path);
      
      // Şifrele
      final key = await E2EKeyService().getLocalKey();
      final encrypted = E2ECryptoService().encryptFile(compressed, key);
      
      // Cloud'a yükle
      final cloudPath = await E2EFileService().uploadBytes(encrypted, file.name);
      
      // Firestore kaydını güncelle
      await _updateFileRecord(file.id, cloudPath);
      
      _reportProgress(
        '${i+1}/${legacyFiles.length} dosya güncellendi',
        (i + 1) / legacyFiles.length,
      );
    }
    
    // 4. Tamamlandı işaretle
    await _markMigrationComplete();
  }
}
```

### 14.3 Background İşlem

```dart
// AutoSyncService içinde
Future<void> triggerE2EMigration() async {
  if (!_isE2EEnabled) return;
  
  final hasLegacyFiles = await _checkLegacyFiles();
  if (!hasLegacyFiles) return;
  
  // WorkManager ile arka planda çalıştır
  await WorkManager().registerOneTaskTask(
    'e2e_migration',
    existingWorkPolicy: ExistingWorkPolicy.append,
    inputData: {'userId': _auth.currentUser!.uid},
  );
}
```

## 19. Geri Alma (Rollback) Planı

```
Eğer E2E encryption ile ilgili ciddi bir sorun olursa:

1. Feature flag: 'e2e_enabled' → false
2. Database version: 17 → 16 (downgrade migration)
3. Yeni service'leri sil veya devre dışı bırak
4. note_repository.dart → eski haline dön
5. file_repository.dart → eski haline dön
6. Auth provider → eski haline dön
7. Kullanıcı verileri etkilenmez (local'de kalır)
8. Cloud'daki .enc dosyaları kalır (erişilemez ama yer kaplar)
   → Temizleme için ayrı script gerekebilir
```

## 20. Riskler ve Çözümler (Güncellenmiş)

| Risk | Olasılık | Etki | Çözüm |
|------|----------|------|-------|
| Şifre unutulursa veri kaybı | **Orta** | **Yüksek** | ✅ Şifre kurtarma sistemi eklenecek |
| İlk yükleme çok yavaş | Düşük | Orta | Background job + compression |
| Cihazda KEY çalınırsa | Çok düşük | Yüksek | Keychain zaten şifreli, ek PIN koruması |
| Firebase storage quota aşımı | Orta | Düşük | Lazy loading, silinen dosyaları temizle |
| Migration sırasında hata | Düşük | Yüksek | Transaction + resume mekanizması |
| Password change sırasında veri kaybı | Çok düşük | Yüksek | Önce yeni KEY oluştur, sonra eski dosyaları çöz-yeniden şifrele |
| Biometric hatası | Orta | Düşük | Password fallback her zaman aktif |
| Şifre kurtarma sonrası eski veriler kaybolur | Orta | Orta | Kullanıcıya açıkça belirt, "veriler sıfırlanacak" uyarısı |
