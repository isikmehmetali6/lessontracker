## 01 — Mimari Kararlar (uygulamadan önce sabitlenir)

### K1. Bulut kayıt şifrelemesi = kullanıcının E2E anahtarı (B2, B10, B12)
- Ayrı `backup_encryption_key` **kaldırılır**. Kayıtlar, zaten parola ile sarılıp `system/e2e_key` kaydında duran **E2E kullanıcı anahtarıyla** şifrelenir → yeni cihazda giriş + parola = anahtar = restore.
- Yeni zarf biçimi (v2): `data = {"v": 2, "encryptedData": base64(nonce[12] ‖ ciphertext ‖ tag[16])}`, **AES-256-GCM** (`encrypt` paketi `AESMode.gcm`), **her kayıt için rastgele nonce**.
- Eski biçim (v alanı yok) = legacy: `backup_encryption_key` + sabit IV ile CBC. Legacy çözme yalnızca **o anahtarın bulunduğu cihazda** mümkün; restore sırasında denenir, bir sonraki backup tüm kayıtları v2'ye yeniden yazar (kendiliğinden göç).
- Guest kullanıcılar etkilenmez (zaten bulut yok).

### K2. E2E anahtar sarma v2 (B10)
- PBKDF2 girdisi `utf8.encode(password)`; çıktı anahtarı GCM ile sarılır; `system/e2e_key` kaydına `kdfVersion: 2` eklenir.
- Çözme sırası: `kdfVersion==2` → utf8+GCM; yoksa legacy (`codeUnits`+CBC). Legacy başarılıysa **aynı oturumda v2 ile yeniden sarılıp upsert edilir**.
- PBKDF2 `compute()` ile isolate'te çalışır (UI donmaz).
- Dosya şifreleme (Storage `.enc`): yeni yüklemeler GCM, dosya başına 4 baytlık sihirli önek `LTG2`; önek yoksa legacy CBC ile çözülür.

### K3. Silmeler = mevcut `pending_changes` tablosu (B4, B7)
- Tablo zaten var (v9) ama yalnızca ders silmede kullanılıyor. Tüm repository `delete*` metotları `AutoSyncService().recordPendingChange(table, id, 'delete')` çağırır.
- `_performBackup`: **önce** bekleyen silmeleri buluta uygular (`CloudRecordsService.delete` + varsa Storage `cloudPath` silme), **sonra** backup; yalnızca başarılı olan satırlar `synced=1` → silinir.
- Silmede `cloudPath` lazım olduğundan kuyruk satırına opsiyonel `payload TEXT` kolonu eklenir (**DB v18 migration**).

### K4. Devamsızlık bulut modeli (B4, B12)
- Ders başına tek kayıt korunur (koleksiyon `absences`, id = courseId) ama içerik v2 şifreli ve `{items: [{id, date, reason}]}`.
- Devamsızlığı kalmamış ders için kayıt **silinir** (şu an eskisi kalıyor).
- Restore id'leri korur (`ConflictAlgorithm.replace`) → idempotent. Legacy `{dates: [...]}` kayıtları için deterministik id: `'${courseId}_${yyyy-MM-dd}'` (AttendanceProvider/AttendanceAutomation ile aynı şema) → tekrar restore çoğaltmaz.

### K5. Veli onayı (B8) — ⚠️ ÜRÜN KARARI GEREKİR
- **Seçenek A (önerilen, ekran ölü kod olduğu için):** `veli_consent_screen.dart`, `veli_onay_dialog.dart`, `supabase/functions/send-veli-verification-email/`, ilgili `veli*` l10n anahtarları silinir; Supabase'den fonksiyon `supabase functions delete` ile kaldırılır.
- **Seçenek B (18 yaş altı onayı yasal gereklilikse):** Kod sunucuda üretilir/doğrulanır. Yeni tablo `parental_consents(user_id, veli_email, code_hash, expires_at, attempts, verified_at)` + RLS; Edge Function iki eylem: `send` (yalnızca kimliği doğrulanmış kullanıcı, `auth.getUser()` kontrolü, kod `crypto.getRandomValues`, SHA-256 hash saklanır, kullanıcı başına DB tabanlı rate limit) ve `verify` (5 deneme limiti). İstemci kodu hiç görmez; `SharedPreferences` kullanımı kalkar. Ekran `AuthWrapper`/signup akışına bağlanır.

## 04 — Riskler ve Geri Dönüş

| Risk | Önlem |
|---|---|
| Legacy yedeği olan ve **yedeği alan cihazı kaybetmiş** kullanıcılar eski kayıtları hiçbir şekilde çözemez (bu zaten bugünkü durum) | Restore sonunda çözülemeyen sayısı gösterilir; veri kaybı yeni değil, yalnızca görünür hale gelir |
| Parolasını e-posta ile sıfırlayan kullanıcı E2E anahtarını çözemez (K1 ile kayıtlar da buna bağlanır) | `_ensureE2EKey` başarısızlığı artık sessiz değil: "Bulut verileriniz eski parolanızla şifreli" ekranı → eski parolayı gir / bulutu sıfırla (`clearCloudData` + yeni anahtar). Kurtarma anahtarı/güvenlik sorusu ile anahtar emaneti → 4b ürün backlog |
| DB v18 migration | Yalnızca `ADD COLUMN` (try/catch ile, v15/v17 deseni) — veri dönüşümü yok |
| GCM'ye geçiş sonrası eski istemci (güncellenmemiş diğer cihaz) v2 kayıtlarını okuyamaz | Sürüm notu; `restore` legacy olmayan kayıtta eski istemcide zaten hata yakalayıp atlıyor (deadline/grade/note try/catch) — **courses döngüsünde try/catch yok, eklenmeli** |
| Silme replay'i yanlış koleksiyonu silerse | Replay yalnızca `(collection, id)` ile tekil silme yapar; `deleteCollection` asla kullanılmaz; test ile kapsanır |
